## 1. 产品目标

**一句话**：把 GridMind 从"能跑"推进到"专业调度员愿意天天用"——补齐"3 秒触达（命令面板）+ 状态透明（Session 可观测）+ 数据决策（KG 灰度可视化）+ 多端可用（响应式/Auto-grid）"四项专业用户日常操作闭环。

**可衡量验收标准（整体）**：

1. 命令面板日活使用率 ≥50%（Q4 OKR，复用竞品分析 §8.3）；
2. 调度员通过命令面板完成跨视图跳转的平均耗时 ≤3 秒（P1-1 核心目标）；
3. 帮助中心自助解决率 ≥80% 常见问题（在应用内找到答案、无需打断式求助）；
4. 调度员可在 10 秒内从 Header 徽标进入 Session drawer 并定位"当前步骤 + 已耗 token + 可回滚节点"；
5. 灰度可视化被采用率 ≥60%（Q4 OKR）；MonitoringView 在 1080p / 2K / 4K 三档分辨率下无横向滚动、图表自动换列；
6. 1024×768 最小分辨率下 5 个核心视图（对话/监控/灰度/审计/系统）全部可用、无遮挡。

## 2. 用户故事

**角色 A：专业调度员（每日 8 小时盯盘）**

- **US1**：作为专业调度员，我想按 ⌘K 直接输入"切到监控"或"回滚到上一步"，以便在不离开当前上下文的情况下 3 秒内完成跨视图跳转与高频操作，减少鼠标点击（日均 -30%）。
- **US2**：作为专业调度员，我需要在任意视图的 Header 随时看到当前 AI session 状态（在跑/暂停/报错），并一键展开看到"AI 跑到哪一步、烧了多少 token、能从哪个 checkpoint 回滚"，以便在异常时立即介入，而不是等 AI 跑完才发现问题。

**角色 B：运维工程师（跨视图导航）**

- **US3**：作为运维工程师，我在部署/排查时需要快速查阅架构与操作文档，按 `?` 即可看到快捷键速查、从帮助中心全文搜索"灰度切流"，以便自助解决 80% 常见问题，不打断排查流程。
- **US4**：作为运维工程师，我在会议室大屏（≥1920）、工位 2K、出差笔记本（1024-1280 紧凑）切换设备时，希望导航自动折叠、图表自动重排，以便任何分辨率下布局都不错乱。

## 3. 需求池（P1 六项）

### P1-1 ⌘K 全局命令面板（增强）—— 工作量 5-7 人天

| 维度 | 内容 |
|---|---|
| **目标** | 专业用户 3 秒内跳转任意路由/操作；高频操作鼠标点击日均 -30% |
| **用户价值** | 8 小时盯盘场景下"跨视图导航 + 高频操作"从点菜单升级为打命令，效率与专业感双提升 |
| **核心交互细节** | ① ⌘K（Mac）/ Ctrl+K（Windows）全局唤起，ESC 关闭，唤起后焦点自动落输入框；② 输入即 fuzzy search，支持**中文/拼音首字母/英文关键字**（如"监控"、"jk"、"monitor"均命中"实时监控"）；③ 结果按分组展示：**路由跳转组 / 常用操作组 / 上下文组**（chat/monitor/rag scope）；④ 键盘 ↑↓ 选择 + Enter 执行，右侧展示快捷键 hint；⑤ 执行后面板自动关闭；⑥ 无匹配时显示空态引导文案"未找到命令，试试：切到监控 / 新建对话" |
| **5 路由** | `/` 智能对话 · `/monitor` 实时监控 · `/grayscale` 灰度面板 · `/audit` HITL 审计 · `/system` 系统总览 |
| **10 常用操作（默认方案，见 §5 待确认）** | ① 新建对话（等价 Header"新对话"）；② 清空当前对话；③ 切换主题（深/浅）；④ 背景模式切换（标准/演示）；⑤ 色盲模式切换（默认/红弱/绿弱/蓝弱）；⑥ 暂停当前推理（仅 running 可用）；⑦ 恢复当前推理（仅 paused 可用）；⑧ 查看 Session 详情（打开 P1-3 drawer）；⑨ 打开 HITL 审计队列（跳 /audit 并高亮待审）；⑩ 回滚到上一步（二次确认） |
| **验收标准** | ① ⌘K/Ctrl+K 全局唤起、ESC 关闭、焦点自动落输入框；② "监控 / jk / monitor"三种输入均命中"实时监控"；③ 5 路由 + 10 操作全部可执行，执行后面板自动关闭；④ 面板在 5 个核心视图（非 onboarding）任意页面可用；⑤ 无匹配时有空态引导 |
| **改动范围** | 增强 `CommandPalette.vue`：新增命令注册中心（useCommands，填充 CommandItem[]）、fuzzy search 算法、结果列表 + 分组渲染、与路由/各 store 对接 action |

### P1-2 帮助中心 + 快捷键速查 —— 工作量 5-7 人天

| 维度 | 内容 |
|---|---|
| **目标** | 调度员/运维在应用内自助解决 80% 常见问题；`?` 键随时看到快捷键总表 |
| **用户价值** | 把散落在 `docs/` 的知识变成应用内可搜索帮助，减少打断式求助，缩短上手与排查路径 |
| **核心交互细节** | ① 新路由 `/help` + `views/HelpCenter.vue`（Markdown 渲染 + 全文搜索）；② `?` 键在任何页面唤起**快捷键速查浮层**（含 ⌘K、`?`、ESC、↑↓、Enter 等全局快捷键总表），ESC 关闭；③ Header 增加帮助入口图标（点开 `/help`）；④ 搜索命中标题/正文高亮，结果分组（文档标题/章节）；⑤ 支持 mermaid 图占位渲染（架构图/流程图） |
| **文档来源默认方案** | **内置精选文档集（推荐）**：从 `docs/` 精选 6-8 篇高频文档，构建时复制为静态资源（如 `web/public/help/*.md`）随前端打包；运行时 fetch 加载 + 前端建全文搜索索引（标题/大纲/关键字）。**不直接读项目根 `docs/`**——前端构建产物部署到独立 Web 服务器后无法访问磁盘 docs/（见 §5 待确认）。默认精选：架构总览、灰度切流指南、HITL 使用指南、快捷键总表、监控面板说明、常见问题 FAQ |
| **验收标准** | ① `/help` 可访问，Markdown 正常渲染（标题/代码块/表格/流程图）；② 全文搜索 ≤100ms 返回结果，命中高亮；③ `?` 键任意页面唤起速查浮层、ESC 关闭；④ 内置 ≥6 篇精选文档，覆盖架构/灰度/HITL/快捷键/监控/FAQ |
| **改动范围** | 新增 `views/HelpCenter.vue` + 速查浮层组件 + 文档资源精选与构建流程（内容由 PM+架构师联合精选） |

### P1-3 Session 状态徽标 + 可观测面板 —— 工作量 5-7 人天

| 维度 | 内容 |
|---|---|
| **目标** | 调度员随时看到"AI 正在做什么、跑了多久、消耗多少 token、能从哪回滚" |
| **用户价值** | 可观测性 +1，黑盒 AI → 透明 AI；异常时即时干预，提升专业用户信任度 |
| **核心交互细节** | ① Header 新增 `SessionBadge.vue`：4 状态 **idle / running / paused / error**，颜色 + 图标 + 文案三重要素（色盲友好，复用 `StatusIcon.vue`）；② running 时徽标脉冲动效，error 时变红 + 抖动提示；③ 点击徽标展开右侧 `SessionDetailDrawer.vue`：**步骤时间线**（step 列表：agent/工具/耗时/状态）、**token 消耗**（累计 + 各步骤占比）、**可回滚节点**（历史 checkpoint 各带"回滚到此步"按钮，二次确认后调 reasoning.rewind）、**运行时长 + 状态流转**；④ idle 时点击提示"当前无进行中的会话" |
| **数据源默认方案** | **优先复用现有 reasoning store + 后端 API**：sessionId、pause/resume/rewind/abort actions、`GET /sessions/{id}/checkpoints`（回滚节点）、`GET /sessions/{id}/state`（重建 steps）、`SSE /sessions/{id}/events`（实时状态流）。**token 消耗**：默认从 SSE events 流的 token 字段聚合；若后端无 token 字段则降级为"步骤数 + 耗时"展示（见 §5 待确认） |
| **验收标准** | ① 徽标在 5 个核心视图 Header 常驻，4 状态颜色+图标可区分（色盲模式下可用）；② 点击徽标 1 秒内打开 drawer，展示步骤时间线 + token + 回滚按钮；③ 回滚有二次确认，成功后时间线刷新；④ idle 时点击有引导提示 |
| **改动范围** | 新增 `SessionBadge.vue` + `SessionDetailDrawer.vue`；`App.vue` Header 挂载徽标；reasoning store 补充状态派生（computed status）与 token 聚合 |

### P1-4 KG 灰度可视化（接 GrayscalePanel.vue）—— 工作量 8-10 人天

| 维度 | 内容 |
|---|---|
| **目标** | 把"灰度切换"从"数字 + 滑块"升级为"知识图谱可视化 + 方案对比" |
| **用户价值** | 灰度决策从"凭经验"升级为"凭数据"（对标雄安智能体多方案打分） |
| **核心交互细节** | ① 页面新增**拓扑视图区**：ECharts 力导向图，展示当前灰度节点（backend A/B）+ 候选节点 + 关联告警/指标；节点大小/颜色编码负载与错误率，支持拖拽/缩放；② **方案对比 tab**：≥3 个方案卡片，每张按维度打分条——**操作开关数量 / 负载率 / 保护适配性**（对标雄安"多套方案打分对比"），含总分；③ **双模式切换**（Coze 灵感）："探索模式"（AI 自动推荐方案，只读）+ "规划模式"（人工勾选节点生成方案，可编辑）；④ 与现有手动切流/回滚联动：选节点 → 生成方案 → "应用"后切流比例更新 |
| **依赖默认方案** | **引入 echarts 依赖**（npm i echarts；按需引入 force/力导向模块控制体积，gzip 后预估 ~350KB）；若体积敏感可封装 vue-echarts。**力导向图数据源**：优先后端 graph 端点；若无，前端先基于 grayscale store 的 status/checkpoints 模拟节点，由架构师确认后端接口（见 §5 待确认） |
| **验收标准** | ① /grayscale 力导向图加载 ≤2s，节点 ≤200 时拖拽/缩放流畅；② 方案对比 tab 展示 ≥3 方案，每方案含 3 维度打分条 + 总分；③ 双模式可切换：探索模式只读、规划模式可勾选/取消节点并生成对比；④ 方案"应用"后与现有切流接口联动，切流比例更新 |
| **改动范围** | `GrayscalePanel.vue` 增加拓扑视图 + 方案对比 tab + 双模式切换；package.json 增加 echarts；与 grayscale store 对接 |

### P1-5 响应式 + 小屏适配（最低 1024×768）—— 工作量 5-7 人天

| 维度 | 内容 |
|---|---|
| **目标** | 调度员在 13 寸笔记本（1280×800）可用，会议室大屏（≥1920）信息密度更高 |
| **用户价值** | 覆盖更广设备类型；同一系统"大屏汇报 / 工位盯盘 / 出差排查"三场景均不布局错乱 |
| **核心交互细节** | ① 系统化 **3 断点**（默认方案）：**≥1920 大屏**——内容区 max-width 放宽（1280→1600），监控图表 4 列铺满；**1280-1920 标准**——维持现状布局（max-width 1280）；**1024-1280 紧凑**——左侧导航折叠为汉堡菜单（el-drawer 展开 5 路由）、Header 右侧状态条精简、统计卡 2 列、监控图表单列/双列；② 紧凑模式附加行为：背景动效自动降级为"标准模式"、FAB 图标化；③ 与 P1-6 联动：紧凑断点下监控页自动单列 |
| **验收标准** | ① 1024×768 下 5 个核心视图无横向滚动、无遮挡、核心操作可达；② 紧凑断点导航折叠为汉堡菜单，抽屉可访问全部 5 路由；③ ≥1920 下监控图表 4 列铺满、无大片留白；④ 响应式改造不破坏 HUD 品牌视觉（tokens 不动） |
| **改动范围** | `App.vue` 断点系统化；导航折叠组件；各视图紧凑态样式（与 P1-6 联动） |

### P1-6 MonitoringView Auto-grid 自适应 —— 工作量 3-5 人天

| 维度 | 内容 |
|---|---|
| **目标** | 监控图表布局自适应不同屏幕（4K / 2K / 1080p），对标 Grafana 12 Auto-grid |
| **用户价值** | 不再"一屏塞满 50 个 panel"或"小屏挤爆"；同一面板在不同设备自动重排 |
| **核心交互细节** | ① **默认方案：CSS Grid `auto-fit + minmax(320px, 1fr)`** 替换固定列模板（`repeat(4,1fr)` → `repeat(2,1fr)` → `1fr`），图表卡片自动换行；② 保留面板内**条件渲染**（无数据面板自动隐藏），减少视觉噪音；③ 与 P1-5 联动：紧凑断点 minmax 下限收窄至 280px |
| **验收标准** | ① 1080p / 2K / 4K 三档分辨率下监控图表自动换列、无横向滚动；② 单面板最小宽度 ≥280px 时可读（标题/数值不截断）；③ 空数据面板自动隐藏；④ 布局变化不触发图表重绘卡顿（防抖） |
| **改动范围** | `MonitoringView.vue` grid 模板替换 + 面板条件渲染 + 断点联动 |

## 5. 待确认问题（附默认方案）

1. **命令面板的 10 个常用操作是否与业务一致？**
   默认方案：已列 10 项（新建对话 / 清空对话 / 切主题 / 背景模式 / 色盲模式 / 暂停推理 / 恢复推理 / 查看 Session / HITL 审计队列 / 回滚上一步）。其中"回滚到上一步"涉及推理状态变更，建议加二次确认——需主理人与调度业务方确认清单与确认策略。

2. **帮助中心文档源：内置精选集 vs 运行时读取 docs/？**
   默认方案：**内置精选文档集**（构建时复制到 `web/public/help/`，随前端打包）。理由：前端构建产物部署到独立 Web 服务器后无法访问项目根磁盘 `docs/`；且 docs/ 含 20+ 篇研发内部文档（architecture/qa 等），不宜全部暴露给用户。需确认：精选 6-8 篇的清单由 PM+架构师联合敲定，以及"文档更新 → 前端发版"的联动机制。

3. **Session token 消耗数据后端是否有 API 支撑？**
   默认方案：优先从 `SSE /sessions/{id}/events` 事件流的 token 字段聚合展示；若后端事件流无 token 字段，则降级为"步骤数 + 耗时"展示，token 区隐藏并标注"待接入"。需后端确认 events 流 schema 是否含 token（含则 P1-3 完整达标，不含则 P1-3 验收标准 ② 中 token 部分降级）。

4. **P1-4 力导向图的节点/边数据来源？**（补充项，与第 3 条可合并决策）
   默认方案：优先后端新增 graph 端点；若后端排期不允许，前端先基于 grayscale store 的 status/checkpoints 模拟节点（≤200 节点），架构师评估后端接口可行性。

## 6. 工作量汇总与优先级排序建议

### 6.1 工作量汇总

| 项 | 竞品分析原估 | 本 PRD 修正估 | 修正理由 |
|---|---|---|---|
| P1-1 命令面板 | 5-7 | 5-7 | 骨架已存在，维持 |
| P1-2 帮助中心 | 5-7 | 5-7 | 内容源现成，维持 |
| P1-3 Session 可观测 | 5-7 | 5-7 | 后端 API 已就绪，可取下限 5 |
| P1-4 KG 灰度 | 8-10 | 8-10 | 新增 echarts + 力导向，最大项 |
| P1-5 响应式 | 5-7 | 5-7 | 与 P1-6 联动，可共用测试 |
| P1-6 Auto-grid | 3-5 | 3-5 | 纯 CSS 替换，最小项 |
| **合计** | **35-45** | **31-41** | 取中值 ~36 人天，4 sprint（8 周） |

### 6.2 优先级排序建议

**第一梯队（先做，见效快 / 为后续铺路）**：
1. **P1-6 Auto-grid**（3-5 人天）——工作量最小、直接提升核心监控页在 1080p/2K/4K 的体验，且为 P1-5 提供改造基础；
2. **P1-1 命令面板**（5-7 人天）——最高频交互入口，骨架已存在，做完即见 Q4 OKR 指标；所有后续"快捷跳转"都依赖它。

**第二梯队（核心价值，紧接第一梯队）**：
3. **P1-3 Session 可观测**（5-7 人天）——后端 API 已就绪、无阻塞，专业用户信任度关键，越早上线越早积累反馈；
4. **P1-2 帮助中心**（5-7 人天）——文档资源现成，主要成本是内容精选 + 渲染 + 搜索，可与 P1-1 的 fuzzy search 复用技术经验。

**第三梯队（较独立 / 依赖后端，可后置）**：
5. **P1-5 响应式**（5-7 人天）——覆盖面广，建议在 P1-6 完成（监控页改造）后实施，避免两处重复改动；
6. **P1-4 KG 灰度**（8-10 人天）——工作量最大、依赖 echarts 引入 + 后端 graph 数据源确认，建议排最后并与后端排期对齐（若后端 graph 端点 Q3 内不可用，可先以前端模拟节点上线探索/规划双模式）。

**排序逻辑**：小步快跑先出可见成果（P1-6 → P1-1），把依赖后端/新增依赖的（P1-4）放最后；P1-3 因后端 API 已就绪可提前插入第二梯队首位。
