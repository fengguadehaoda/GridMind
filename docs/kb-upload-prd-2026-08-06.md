# PRD · GridMind 用户上传知识库（KB Upload）

> 文档版本：v1.0 · 2026-08-06
> 产品负责人：许清楚（GridMind 产品经理）
> 关联需求：用户在前端界面自助上传知识文档，扩展对话 RAG 的知识来源
> 复用既有链路（V1.6 已交付）：
> - SQLite `knowledge_chunks` 表（chunk_id / doc_id / title / content / source + tags / icon / starter_message / meta / updated_at）
> - `core/vector_store.py` 的 `VectorStore`（collection='knowledge_base'，`upsert_chunks` / `search_by_tag` / `get_vector_store` / `ensure_fresh` 跨进程热更新）
> - `kb_meta` 表（kb_revision 版本号，热更新机制）
> - RAG 引擎 `core/rag_engine.py`（retrieve / answer）
> - 鉴权 `api/services/auth.py`（`verify_jwt_token` / `verify_jwt_if_prod`：生产强制、dev 放行）
> - 现有 doc_id 命名空间：`feature-intro:...`（本功能须与之隔离）

---

## 1. 产品目标

**一句话目标**：让具备权限的用户在前端自助上传 txt/md（pdf 见 P1）知识文档，经解析切分后入库 GridMind 知识库（SQLite + Chroma），使新增知识在对话 RAG 中可被检索问答，并与既有内置知识（feature-intro）互不干扰、可由管理员统一维护。

**可衡量的验收标准**：

1. 用户在「知识库管理」上传 txt/md 文件，上传成功后 **10s 内**（含解析、切分、入库、热更新生效）可在对话 RAG 中检索到该文档内容并正确作答。
2. 上传链路全程有明确状态反馈：文件校验（格式 / 大小）→ 上传进度 → 解析入库成功 / 失败提示；失败时给出可理解的错误文案，不出现静默失败或空白页。
3. 用户上传文档以独立命名空间 `user-upload:...` 入库，与既有 `feature-intro:...` 互不覆盖、互不冲突；删除 / 覆盖操作只影响用户上传知识，不影响内置知识。
4. 知识管理员可查看已上传文件列表，并看到每份文档的入库状态与 chunk 数量；可删除误传文档。
5. 所有上传 / 删除操作均经鉴权（生产环境强制 JWT，dev 放行），未授权请求被拒绝。

---

## 2. 用户故事

- **作为电网运维工程师**：我希望上传设备手册 / 操作规程（如《#T1 主变操作票》）后，能直接在对话里问「#T1 主变操作票中紧急停机步骤是什么」，以便现场处置时快速引用最新规程，不用翻纸质文档或等别人转述。
- **作为知识管理员**：我希望批量维护知识文档（上传、查看、删除），并能看到每份文档切分成了多少个片段，以便确认知识已正确入库、及时清理过期材料。
- **作为知识管理员**：我希望误传 / 过期的文档可以删除、同名文档可以覆盖更新，以便知识库内容始终与最新版一致，不积累脏数据。

## 3. 需求池（P0 / P1 / P2）

### P0（Must have · 本期必须交付）

- **P0-1 前端上传入口与交互**：帮助中心新增「知识库管理」Tab，提供文件选择 / 拖拽上传、上传进度、成功 / 失败结果反馈（含错误文案）。
- **P0-2 后端解析入库**：接收上传文件，解析 txt / md → 切分 chunk → 写入 SQLite `knowledge_chunks` + Chroma 向量库，并更新 `kb_meta` 版本号触发热更新。
- **P0-3 命名空间隔离**：用户上传 doc_id 统一使用 `user-upload:{uuid}` 前缀，与 `feature-intro:...` 完全隔离；检索、删除、覆盖均限定在该命名空间内。
- **P0-4 对话 RAG 可检索**：上传完成后新知识可被 `rag_engine` 检索到（复用 `VectorStore.upsert_chunks` + `ensure_fresh`），验收见 §1。
- **P0-5 鉴权**：上传 / 删除接口经 `verify_jwt_token` / `verify_jwt_if_prod` 保护（生产强制、dev 放行）。

### P1（Should have · 强烈建议本期交付）

- **P1-1 支持 pdf 格式**：文本型 PDF 解析入库；扫描件不做 OCR，给出明确提示。
- **P1-2 文件列表 / 删除**：展示已上传文件（名称、大小、上传时间、状态），支持删除。
- **P1-3 按文档查看已入库 chunk 数**：便于管理员确认切分效果。
- **P1-4 文件大小限制与格式校验**：默认单文件 ≤ 5MB，仅允许 txt / md（pdf 加入时扩充）；超限 / 格式不符给出明确错误提示。

### P2（Nice to have · 后续迭代）

- **P2-1 同名文件重传覆盖更新**：重传同名文档时更新其分片（保留旧分片清理策略）。
- **P2-2 多语言文档**：上传时标注语言，检索时按语言匹配。

## 4. UI / 文案设计稿

### 4.1 上传入口（默认方案）

- 默认放在**帮助中心（HelpCenter）**新增「知识库管理」Tab；若 HelpCenter 不便扩展，退而放在**系统总览（SystemOverview）**增加「知识库」卡片入口。
- 入口文案：「知识库管理」；主操作按钮：「上传文档」。

### 4.2 上传组件交互

1. **选择区**：拖拽 / 点击选择文件，提示「点击或拖拽文件到此处上传」，支持多选。
2. **校验失败**：格式 / 大小不合规时即时提示，如「仅支持 txt / md 文件」「文件大小不能超过 5MB」。
3. **上传中**：显示进度条 + 文件名；解析入库阶段显示「正在解析入库…」。
4. **成功**：提示「已上传，解析入库完成，共生成 N 个知识片段，可在对话中检索」。
5. **失败**：显示失败原因（格式不支持 / 解析失败 / 服务异常），允许重试。

> 成功文案示例：`《#T1 主变操作票.md》已入库，共 12 个知识片段，现在可以在对话中提问相关规程。`

### 4.3 文件列表展示

表格列：文件名 / 大小 / 上传时间 / 状态（处理中 / 已入库 / 失败）/ 知识片段数 / 操作（删除）。
- 状态「处理中」时禁用删除；
- 状态「失败」时提供「重试」；
- 删除需二次确认，提示「删除后该文档的知识将无法在对话中检索」。

## 5. 待确认问题（默认方案）

1. **支持格式**：默认 txt / md，pdf 列为 P1；是否接受此划分？（扫描版 PDF 是否需 OCR 需另行评估，默认不做）
2. **上传入口位置**：默认 HelpCenter「知识库管理」Tab；如希望放 SystemOverview 卡片，请明确。
3. **doc_id 命名规范**：默认 `user-upload:{uuid}`（uuid 后端生成），与 `feature-intro:...` 隔离；是否接受？
4. **文件大小上限**：默认单文件 5MB；是否需要按格式区分（如 pdf 可放宽）？
5. **是否按用户隔离**：默认全局共享（上传后所有用户可见、可被 RAG 检索），不做多租户隔离；是否需要按用户 / 角色隔离？
6. **删除策略**：删除后默认物理删除 SQLite + Chroma 分片并同步版本号，且删除动作写入审计日志；是否接受？
