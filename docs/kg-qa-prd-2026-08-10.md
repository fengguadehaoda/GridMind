## 一、产品目标（一句话）

把知识图谱从「后台检索」变成「前台可问」：调度员用自然语言提问，得到**可验证的图谱路径可视化答案**（节点-边推理路径 + 来源引用），在 Neo4j 不可用时自动降级为 NetworkX + 路径文字，保证任何环境都能演示、可用、可信。

## 二、用户故事（含验收标准）

> 验收标准采用 must（必须）/should（应该）/could（可以）措辞；全部可自动化断言。

### US-1 图谱问答 + 图谱路径可视化（P0）
**As a 调度员, I want 用自然语言问"变压器过载会影响哪些设备"并看到节点-边图谱路径, so that 我能直观看到 AI 答案的推理依据。**

验收标准：
- must：提问命中 knowledge_agent 时，响应含 `graph_answer`（非空）；
- must：`graph_answer.nodes` 至少含 1 个 seed 节点（由 `_extract_entity_ids` 从问题+检索上下文提取）及其 1/2 跳可达节点；
- must：`graph_answer.edges` 每条含 `relation_type`（如 触发/导致/包含/关联/处置）；
- must：`graph_answer.paths` ≥ 1 条，且与前端图谱渲染同源（同一轮 query 的同一份数据）；
- must：图谱面板出现在回答气泡内（RagPanel 内嵌 GraphQAPanel），不跳转新页面；
- should：seed 节点高亮，边标签显示关系类型，节点颜色按实体类型区分。

### US-2 图谱图交互：hover 详情 + 点击联动来源（P1）
**As a 调度员, I want 悬停节点查看详情、点击节点查看关联来源, so that 我能验证每个实体为什么出现在推理路径里。**

验收标准：
- must：节点 hover 显示 tooltip（名称/实体类型/关键属性/距 seed 跳数/关联来源数），0.3s 内出现；
- must：点击节点弹出实体详情（属性表 + 关联来源 CitationCard 列表 + doc_id 复制按钮）；
- must：tooltip 文本沿用 `escapeTooltip()` 转义，杜绝 HTML 注入（保持 F8 缓解策略）；
- should：详情中来源可展开原文（复用 CitationCard 现有行为）；
- could：点击实体详情中的来源 → 定位/跳转知识库对应文档（依赖待确认 #1 的文档浏览视图，P2 若立项）。

### US-3 多跳路径层级展示（P1）
**As a 调度员, I want 看到 1 跳/2 跳/3 跳的路径层级, so that 我能理解推理链的深度与可信度。**

验收标准：
- must：路径列表按跳数分组/排序，显示每条路径的跳数与置信度；
- must：图谱节点按 hop 着色（seed=0 高亮、1 跳、2 跳、3 跳渐变色）；
- must：hops 上限 3（工具支持 1-5，前端默认 3，超出截断并在面板标注）；
- should：`graph_answer.paths[].confidence` 随跳数递减（沿用 `max(0, 1 - hops*0.15)` 口径），前端在路径行展示。

### US-4 降级路径：Neo4j 不可用时仍可问答（P0 后端 / P1 展示）
**As a 调度员, I want 在 Neo4j 未部署/宕机时依然能问图谱问题, so that 系统不因图谱后端故障而不可用。**

验收标准：
- must：`backend == "networkx"` 时 `graph_answer.degraded == true`，问答本身（RAG 回答）不受影响；
- must：NetworkX 下 nodes/edges 非空 → 图谱图**正常渲染**（NetworkX 内存图同样有实体与关系）；
- must：nodes/edges 为空或后端异常 → 前端**降级为路径文字展示**（复用现有 graph_paths 文本 collapse），不白屏、不报错；
- should：图谱面板顶部显示 backend 徽标（`neo4j` / `networkx`），degraded 时给弱提示（"当前为降级图谱，数据有限"）；
- should：mock/演示模式（无 LLM Key）下知识剧本（过载/油温/停机检修）也携带 mock `graph_answer`，保证演示可见图谱面板。

### US-5 与 M-3 来源引用链协同（P0）
**As a 调度员, I want 图谱答案也带来源引用, so that 图谱路径与文档依据能互相印证。**

验收标准：
- must：`GraphAnswer.sources` 与同轮 `KnowledgeAnswer.sources` 一致或为其子集；
- must：来源卡片区（RagPanel 的 CitationCard + DocFilterChips）在图谱面板之外正常渲染，不因 graph_answer 引入而破坏 M-3 行为；
- should：点击图谱节点后，详情浮层的"关联来源"与来源卡片区指向同一批 doc_id；
- must：旧后端/旧数据无 `graph_answer` 时，KnowledgeAnswer 其余字段行为与 M-3 完全一致（向后兼容）。

## 四、数据结构草案（图谱问答响应 schema）

> 对齐现有 Pydantic 风格（snake_case、字段可选降级）；`GraphAnswer` 作为 `KnowledgeAnswer.graph_answer` 的可选字段下发。

```python
# api/schemas/__init__.py 增量（P0-2）
class GraphAnswerNode(BaseModel):
    id: str
    name: str
    type: str                       # 设备类别/故障类型/处置措施/规程/部件/…
    properties: dict[str, Any] = {}  # 复用 KG 实体 properties
    hop: int | None = None          # 距 seed 的跳数（seed=0）；未知 → None
    doc_ids: list[str] = []         # 关联文档（实体→来源映射，P1 填充）
    confidence: float | None = None # 节点级置信度（可选）

class GraphAnswerEdge(BaseModel):
    source: str                     # 节点 id
    target: str
    relation_type: str              # 触发/导致/包含/关联/处置/CAUSES/…
    confidence: float | None = None
    rule_id: str | None = None      # 推理规则来源（P2 规则边时非空）

class GraphPath(BaseModel):
    nodes: list[str]                # 节点 id 序列（有序）
    relations: list[str]            # 关系类型序列（len = nodes - 1）
    hops: int
    confidence: float               # 沿用 max(0, 1 - hops*0.15) 口径

class GraphAnswer(BaseModel):
    nodes: list[GraphAnswerNode] = []
    edges: list[GraphAnswerEdge] = []
    paths: list[GraphPath] = []
    seed_ids: list[str] = []        # 本轮实体抽取的 seed
    confidence: float = 0.0         # 综合置信度（P0 用 min/加权，见待确认 #2）
    backend: str = "networkx"       # "neo4j" | "networkx"
    degraded: bool = False          # True = 降级后端/部分数据
    latency_ms: float = 0.0
    sources: list[SourceRef] = []   # M-3 协同（US-5）

# KnowledgeAnswer 增量（向后兼容：旧数据无此字段）
class KnowledgeAnswer(BaseModel):
    ...
    graph_answer: GraphAnswer | None = None   # M-4 新增；无图谱问答时 None
```

前端镜像（`web/src/types/index.ts`）：`GraphAnswerNode / GraphAnswerEdge / GraphPath / GraphAnswer`，`KnowledgeAnswer.graph_answer?: GraphAnswer | null`。

**数据流**：
```
用户提问
  → knowledge_agent（AGENT_TOOLS_MAP 已含 kg_multi_hop_reason/kg_apply_rules）
  → query_knowledge_base（RagEngine.answer：向量+图谱扩展）
  → 图谱问答编排（GraphQAEngine：实体抽取 → expand_with_optimizer → GraphAnswer）
  → KnowledgeAnswer{answer, sources, graph_answer}
  → SSE done 事件（现有 knowledge_answer 通道，零新端点）
  → chatStore.attachContext → MessageBubble → RagPanel → GraphQAPanel（ForceGraphView）
```

## 六、与 RBAC 的关系

- **图谱问答为只读能力**，随 `/chat`、`/chat/stream` 现有鉴权链路下发（`verify_thread_ownership_if_prod`），**不新增鉴权面**，天然符合"KB 读全员"策略（dispatcher/operator/kb_admin/auditor/admin 均可问）。
- 图谱问答**不产生写操作**（不触发 HITL、不落库变更），`graph_answer` 仅作为回答元数据透传；KB 写权限（kb_admin/admin）不受影响、不扩展。
- 若 P2-4 立项独立只读端点 `/api/kg/qa`，复用 `verify_jwt_if_prod` 即可（读全员），无需 `require_role` 限制。
- 待确认（#6）：图谱答案若含设备实时状态等敏感字段，是否需要按角色裁剪（建议：不需要，与 KB 读全员一致；后续如需再评估）。
